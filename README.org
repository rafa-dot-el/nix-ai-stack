#+title: nix-ai-stack: AI agents, MCP servers and tools for NixOS and Home Manager
#+author: Rafael
#+language: en

* Overview

One Nix flake for an AI workstation: agents (Hermes, Claude Code, goose,
Antigravity), first-party MCP servers and CLIs, and one =mcp= proxy that puts
every server behind its own socket-activated systemd user service. Everything
is built from source or pinned by hash, and every wrapper ships with self-update
and telemetry switched off (ADR-0002).

The consumer surface is one option tree, =rafa.ai=, on both NixOS and Home
Manager (ADR-0006), plus =overlays.default= (=pkgs.rafa.ai.<name>=) and
=packages.<system>.*=.

#+end_src

Add =nix-ai-stack.nixosModules.default= to a NixOS configuration and
=nix-ai-stack.homeManagerModules.default= to a Home Manager one.

** Home Manager

Each agent has one root switch that turns on its default stack. Long-running
services never follow a root switch.

#+begin_src nix :eval no
{
  rafa.ai = {
    agents.claude.enable = true;        # code + acp + desktop + usage (CLI, polybar)
    agents.hermes.enable = true;        # CLI, TUI, ACP, desktop, hardened config fragment
    agents.antigravity.enable = true;

    tools = {
      openspec.enable = true;
      plannotator.enable = true;
      slack = {
        enable = true;
        settings = {
          credentials.token.command = [ "pass" "show" "slack/token" ];
          policy = { default = "deny"; rules = [ { match.self_dm = true; action = "live"; } ]; };
        };
      };
    };

    # voice is on by default: one Piper voice and Whisper model for every tool
    voice.tts.voice = "en_GB-alba-medium";

    mcp = {
      enable = true;
      servers.slack.enable = true;
      servers.gtasks.enable = true;
      servers.playwright.enable = true;
      profiles.coding.servers = {
        playwright.include = [ "browser_*" ];
        gtasks.include = [ "list_*" "get_task" ];
      };
    };
  };
}
#+end_src

Point an agent at a profile with =mcp client --profile coding= as its stdio
MCP command.

Secrets are always references (={ command = [...]; }= or ={ file = ...; }=),
resolved by the tool at start-up. They are never written to the Nix store or a
unit file.

* MCP stack

#+begin_example
agent --stdio--> mcp client --profile P --unix--> mcp proxy --unix--> %t/rafa/mcp/servers/<name>.sock
                                                                       (mcp-<name>.socket activates mcp-<name>.service)
#+end_example

- The proxy finds servers by watching the pool directory; no server list is
  needed. Each server is its own service with its own journal identifier
  (=journalctl --user -u mcp-slack=).
- Filters run on both sides: =include=, =exclude= (exclude wins), =rename=,
  =describe=, matched on the original tool name. Two tools with the same
  exposed name are an error, never resolved silently.
- Config: Home Manager writes =~/.config/rafa/mcp.d/10-nix.yaml=; your own
  =~/.config/rafa/mcp.yaml= is edited with =mcp config ...= or
  =mcp config-tui=. A project's =.rafa/mcp.yaml= loads only with =--project=.
- =mcp doctor= checks the config, the health of the proxy and every server,
  and the token savings of each profile.

Presets in =rafa.ai.mcp.servers=: =slack=, =gtasks=, =gdocs=, =gsheets=,
=gcal=, =gdrive=, =gmail=, =gmeet=, =tmpmail=, =calibre=, =zotero=,
=playwright=, =patternfly=, =likec4=.

* Hermes

** Hermes dashboard and gateway (NixOS)

=rafa.ai.agents.hermes.server= (the old =rafa.ai.agents.hermes.server= name still works as an alias) runs the web dashboard (=hermes dashboard=) and/or the messaging gateway (=hermes gateway=) as their own systemd services — always two separate processes, coordinating only through the shared =hermesHome=, never directly (verified against upstream's own module comments: the dashboard backend "does not run the messaging gateway... it does not contain a gateway"). This is a small, purpose-built module; upstream's fuller option surface (MCP servers, container mode, declarative config) is explicit future work, not available here yet.

Shared options live at =rafa.ai.agents.hermes.server.*= (=package=, =user=/=group=, =stateDir=, =hermesHome=, and the =lsp=/=voice=/=browser=/=gateway= feature toggles below); everything dashboard-specific is under =rafa.ai.agents.hermes.server.dashboard.*=, mirroring the split upstream uses between its shared options and its own =backend.*= sub-namespace. =package= defaults to a build with exactly the enabled features — the Electron desktop app is *never* included, regardless of the toggles below (neither service needs it, and skipping it avoids an unnecessary Electron/Chromium-for-Electron dependency closure on a headless host).

#+begin_src nix :eval no
{
  rafa.ai.agents.hermes.server = {
    # hermesHome defaults to "${stateDir}/.hermes" — override to point it at
    # a separate volume. This is persistent application state (config.yaml,
    # sessions, memory, cron), not scratch/tmp. Shared between dashboard and
    # gateway when both are enabled — that's how they coordinate.
    hermesHome = "/var/lib/hermes-agent/.hermes";

    # Feature toggles for `package` — each true by default; set any to
    # false to shrink the closure (e.g. a gateway-only host with no browser
    # automation needed can set browser.enable = false).
    lsp.enable = true;
    voice.enable = true;
    browser.enable = true;

    gateway = {
      enable = true;  # also controls whether messaging/matrix extras are in `package`
      extraArgs = [ ];
    };

    dashboard = {
      enable = true;
      bindAddress = "0.0.0.0";  # default; only applies when `domain` is unset — see below
      port = 8080;              # default when `domain` is unset (unprivileged); 443 when it is — only nginx ever binds a privileged port
      openFirewall = true;

      # Optional: Let's Encrypt TLS via an nginx reverse proxy.
      domain = "hermes.example.com";

      # Optional: HTTP Basic Auth in front of it (requires `domain`).
      basicAuth = {
        enable = true;
        passwordFile = "/run/secrets/hermes-dashboard-htpasswd"; # htpasswd -c ...; never a Nix store path
      };

      # Optional: mutual TLS client-certificate verification (requires `domain`).
      # caFile is a CA cert (public, fine as a Nix store path) — can combine
      # with basicAuth, or use verifyOptional = true for cert-or-password.
      mTLS = {
        enable = true;
        caFile = ./my-client-ca.pem;
      };
    };
  };

  # Required by NixOS whenever any vhost has enableACME (not set for you —
  # accepting Let's Encrypt's subscriber agreement is your decision):
  security.acme.acceptTerms = true;
  security.acme.defaults.email = "you@example.com";
}
#+end_src

Without =domain=, the dashboard binds directly on =bindAddress=:=port= with no TLS layer — fine for a Tailscale/VPN-only setup, not for the open internet. Whenever =domain= *is* set, the dashboard process is always forced to =127.0.0.1= regardless of =bindAddress=, so the TLS+auth front door can't be bypassed on the local network.

PAM-based auth was considered and deliberately left out — it would need a custom nginx build plus giving the nginx worker access to a shadow-backed PAM stack, a materially larger attack surface than basicAuth/mTLS for a network-facing daemon. Left as explicit future work if actually needed.

** Configuration

Hermes reads its TTS and STT from the shared voice (=rafa.ai.voice=):
=~/.config/rafa/voice.yaml= and the stable links under
=~/.local/share/rafa/voice/{tts,stt}=.

*** Browser automation (browser-use + agent-browser)

The CLI has two browser backends:
- *browser-use*: Autonomous agent-driven browser control (=browser_exec=, the default backend — active whenever the =browser-use= CLI is on PATH, which it always is in this package)
- *agent-browser*: Built-in browser toolset for hermes_agent (CDP-driven)

Hermes starts its own Chromium on demand: the first =browser_exec= call of a
session launches the packaged Chromium through =agent-browser= (upstream's
=_resolve_managed_chromium_cdp=). Nothing has to be running beforehand, and
nothing starts at =hermes= startup. The packaged Chromium runs headless, so it
needs no display.

A CDP endpoint configured by the operator (=BROWSER_CDP_URL=, =BU_CDP_URL=,
=BU_CDP_WS=, or =browser.cdp_url= in config.yaml) takes precedence and is used
as-is; Hermes does not launch anything in that case.

*** Hardening (no self-update, no telemetry)

Every wrapper defaults the variables in =lib/hardening.nix= (=--set-default=,
so any of them can still be overridden): Hermes's runtime package installs
(=HERMES_DISABLE_LAZY_INSTALLS=), browser-harness and browser-use telemetry and
update checks, the browser-use extension download, cua-driver telemetry and its
release check, and Hugging Face telemetry. The browser comes from Nix: Hermes
never downloads a Chromium into =HERMES_HOME/tools=.

Some switches only exist in =config.yaml=. The package ships them as
=share/hermes-agent/hardened-config.yaml= to merge into a profile:

#+begin_src yaml :eval no
updates: {check: false}
plugins: {auto_update_check_hours: 0}
model_catalog: {enabled: false}
security: {allow_lazy_installs: false}
lsp: {install_strategy: manual}
telemetry: {shared_metrics: {enabled: false}}
#+end_src

What cannot be switched off (verified against the source):
- Hermes fetches =models.dev/api.json= for model metadata; only its URL is configurable.
- =browser-harness --doctor= and =--update= contact PyPI when run explicitly.

=checks.hardening= verifies every wrapper sets each variable, sets none of the
forbidden ones, and that =hermes --version= makes no off-host =connect()=.

*** Integration tests

=tests/integration= drives =hermes-acp= (the ACP front door an editor uses)
against a scripted fake of the OpenAI Chat Completions API, so the model's
turns are fixed and the assertions are on what Hermes sent the backend and on
the browser it actually drove.

#+begin_src bash :eval no
task test:unit          # the fake backend itself: pure Python, no nix build
task test:integration   # builds the package, then runs everything (needs network for the Cat test)
task test:integration -- -m "not network"   # offline subset
#+end_src

Each test gets its own profile, HOME, TMPDIR and agent-browser/browser-harness
runtime dirs under =/tmp/hi-*=, and tears down what it started. Set
=HERMES_IT_KEEP_SESSIONS=1= to keep those directories after a run for debugging.

*** Wake word (sherpa)

Configured via config.yaml:

#+begin_src yaml :eval no
wake_word:
  provider: sherpa
#+end_src

Default supports any phrase in English; no training needed.

* Docker Hub

=rafadotel/ai= on Docker Hub is =hermesFull= packaged as an OCI image (built via =pkgs.dockerTools.buildLayeredImage=, no Dockerfile). Currently =linux/amd64= only — =arm64= isn't wired into CI yet (see =task oci:push= below to publish one by hand from an aarch64 host).

#+begin_src bash :eval no
docker pull rafadotel/ai:latest
docker run --rm -it rafadotel/ai:latest
#+end_src

Tags: =latest= (tracks =main=) and a version tag per release (e.g. =2026.8.27=, matching the git tag without its leading "v").

* Troubleshooting

** Piper TTS not found

Check the stable links the voice module writes:

#+begin_src bash :eval no
ls -la ~/.local/share/rafa/voice/tts ~/.local/share/rafa/voice/stt
cat ~/.config/rafa/voice.yaml
#+end_src

** Browser automation not working

Check the agent log for the browser session that =browser_exec= creates:

#+begin_src bash :eval no
grep -E "Created local browser session|browser_exec" "${HERMES_HOME:-$HOME/.hermes}/logs/agent.log" | tail -5
#+end_src

If the session never starts, the =browser_exec= result carries the failure
from browser-harness or agent-browser in its =stderr=.

A CDP endpoint configured through =BROWSER_CDP_URL=/=BU_CDP_URL=/=BU_CDP_WS=
or =browser.cdp_url= in config.yaml is used instead of the packaged Chromium,
so if one is set, check that it is reachable.

Ensure Chromium itself is on PATH:

#+begin_src bash :eval no
which chromium
#+end_src

If not found, verify the Hermes package is correctly installed with extraPathTools.

** LSP server not detected

Verify the server is on PATH:

#+begin_src bash :eval no
which pyright typescript-language-server gopls rust-analyzer clangd nixd
#+end_src

Configure in Hermes: =lsp.install_strategy: manual= in config.yaml.

** Build timeout or OOM

If building locally (without Cachix), the build is resource-intensive (~30 min on modern hardware, ~8GB RAM). Use the binary cache or increase system resources.
